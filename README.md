# Telegram-каталог материалов (FastAPI + aiogram3 + Google Sheets)

Проект позволяет быстро запустить Telegram-бота с прикрепленным Mini App для выбора товаров из каталога, где всё управление базой данных ведется через Google Sheets, а фотографии лежат на Google Drive. Никакой админки не нужно!

## 1. Подготовка Google Sheets и Service Account

1. **Создание таблицы**: Создайте новую Google Таблицу. Бот сам создаст нужные листы (`Catalog`, `Clients`, `Selections`) при первом запуске, если они отсутствуют.
2. **Service Account**:
   - Перейдите в [Google Cloud Console](https://console.cloud.google.com/).
   - Создайте проект -> перейдите в **IAM & Admin** -> **Service Accounts**.
   - Создайте Service Account, сгенерируйте для него ключ в формате JSON. Скопируйте содержимое этого JSON-файла – оно понадобится для переменной `GOOGLE_SERVICE_ACCOUNT_JSON`.
   - Скопируйте `client_email` из созданного Service Account.
3. **Предоставление доступа**: Откройте вашу Google Таблицу и выдайте права **"Редактор" (Editor)** на скопированный `client_email`.
4. **Google Drive API и Sheets API**: В Google Cloud Console перейдите в **APIs & Services** и убедитесь, что включены **Google Sheets API** и **Google Drive API**.

## 2. Настройка Google Apps Script (Авто-обновление кэша)
Чтобы бот мгновенно обновлял каталог при изменении таблицы (а не ждал 60 секунд), нужно настроить триггер:
1. В Google Таблице нажмите `Расширения` -> `Apps Script`.
2. Вставьте код из файла `apps_script.js` (обязательно заменив URL в коде на адрес вашего Railway-бэкенда).
3. В левом меню нажмите на иконку часов (**Триггеры**).
4. Нажмите `Добавить триггер`:
   - Выберите функцию: `triggerOnEdit`
   - Источник мероприятия: `Из таблицы`
   - Тип мероприятия: `При редактировании`
5. Сохраните и выдайте запрошенные Google разрешения.

## 3. Рекомендации по ведению Google Sheets (Data Validation)
Для листа `Catalog` рекомендуется настроить проверку данных (Data Validation), чтобы сотрудники не ошибались при вводе:
- **Колонка `status`**: Выделите колонку -> *Вставка* -> *Раскрывающийся список* (Dropdown). Пропишите варианты: `В наличии`, `Под заказ`, `Отсутствует`. Фронтенд автоматически заблокирует кнопку "Добавить", если статус не содержит "в наличии".
- **Колонка `visible`**: Выделите колонку -> *Вставка* -> *Флажок* (Checkbox). Отмеченный чекбокс = `TRUE`, пустой = `FALSE`. Бот грузит только `visible=TRUE`.
- **Колонка `unit`**: Раскрывающийся список (`шт`, `м²`, `пог.м`, `уп`).
- **Фотографии (`image_url`)**: Сотрудники загружают фото на свой Google Drive -> правой кнопкой мыши -> *Поделиться* -> *Доступно всем, у кого есть ссылка*. Копируют эту ссылку и вставляют в колонку. Бот сам конвертирует её в прямую ссылку для отображения в Mini App.

## 4. Создание Бота и Mini App
1. Перейдите к [@BotFather](https://t.me/BotFather) в Telegram и создайте нового бота (`/newbot`). Получите токен (это `TELEGRAM_BOT_TOKEN`).
2. Опубликуйте фронтенд (Mini App) - файл `webapp/index.html` можно бесплатно захостить на GitHub Pages, Vercel или Netlify. Полученную ссылку скопируйте — это `MINIAPP_URL`.
3. У бота настройте кнопку меню: в BotFather введите `/setmenubutton`, выберите вашего бота и укажите ссылку на ваш задеплоенный Mini App.

## 5. Деплой одной командой на Railway
Проект полностью готов для деплоя на [Railway](https://railway.app). Архитектура запускает и FastAPI, и поллинг Telegram-бота в одном процессе.
1. Создайте новый проект из вашего GitHub репозитория.
2. В разделе **Variables** пропишите все переменные из файла `.env.example`:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
   - `STAFF_CHAT_ID` — ID чата/группы, куда бот будет присылать уведомления о новых заказах (можно узнать через @userinfobot).
   - `GOOGLE_SERVICE_ACCOUNT_JSON` — JSON-ключ целиком в одну строку.
   - `SPREADSHEET_NAME` — точное название вашей таблицы.
   - `MINIAPP_URL` — ссылка на размещенный `index.html`.
3. Railway автоматически распознает `railway.json`, установит зависимости из `requirements.txt` и запустит проект одной командой. Бот и веб-сервер будут работать одновременно!
